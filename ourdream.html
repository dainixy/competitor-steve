Standout & Actions for Steve Session complete · 2026-05-18

OurDream is the best all-round AI companion platform in the category — and it's not a companion product, it's a creative media studio with companion elements bolted on. Users come for the characters, stay for the generation tools, and get hooked on building and discovering community content. The companion feel is real but secondary: the chat quality is "okay but not wow" and the voice call is functional but passive. What's exceptional is everything around the conversation — the image gen, the video studio, the creator economy, the UX polish, and the business model. Dainis verdict: "a mix of Kindroid and GPT — better balance, more depth than GPT, but calls are the weakest part." The community flywheel (creators → content → discovery → unlock purchases → more creators) is the core differentiator and is already spinning fast. 10M users, 50M pieces of media, 300M messages in under a year.

Steal immediately for DRT.FM

  • In-app helpdesk hub (Bugs / Features / Changelog). Premium-gated, all in one in-app panel, clean tabbed UI. Dainis: "my favourite feature — better than GGPT's Beamer, want to steal it." Gives users a voice, gives the team intelligence, signals transparency. Build this.
  • Cancellation flow. Step 1: reason dropdown (Chat Quality / Image Quality / Expensive / Avoid Recurring Billing / Video Quality / Just Trialling / Other). Step 2: "We understand" — coin bonus offer (3,000 coins, awarded the day before the billing period ends). Step 3: "We are going to miss you!" final confirmation with personalised impact preview ("you will lose access to your 5 videos and 49 images" — counts pulled from the user's own library). Step 4: even if they cancel, they keep the goodwill coins. Non-hostile, no guilt, no dark patterns. Best cancel UX in the category.
  • Lust Level slider + per-chat writing style panel. 5-level arousal control (😒 → 💀, from "playful and suggestive" to "sexually forward, fast escalation, anatomically detailed"). AI model picker (Standard / Thinking / Experimental), response length, chat mode (Roleplay vs Texting) — all per-character, not global. Gives users granular control without overwhelming them.
  • Background generation + notification bell. Every generation (image, video, audio) runs async. Text always arrives first. Gallery accumulates passively. Notification bell tracks job status. Users never wait at a loading screen. This is the correct architecture for a generation-heavy product.
  • Content unlock model. Every public character has a community-built library. Pay once in coins (scales with library size: 250–1,000 coins), get all current + future content. OurDream pays $0 for the content — community generates it. Three-tap funnel: Feed scroll → character card → Unlock All Content. Kylie Bennett: 21K images + 665 videos for 1,000 coins.
  • Dreamer Program creator ladder. Rising Dreamer (~50K interactions) → Lucid Dreamer (300K interactions, earn 100 coins per community pack purchase) → Dream Architect (coming soon: cash payouts). Fast-track for creators from other platforms. The program does the content recruitment so the platform doesn't have to.

Avoid / counter-position

  • Context header in every response. Date / time / location / weather prefixed on every AI message. Works in immersive text roleplay; becomes noise in voice calls and clutters the chat list preview. Don't do this as a default.
  • Passive voice call. No video, no initiation — she waits for the user to speak. Makes the call feel like a phone tree, not an intimate conversation. Kindroid's talking-head video call is the correct benchmark. Don't ship voice without initiation logic.
  • Silent limit reductions. The April 20 changelog entry that capped Pinned Memories to 15K was mislabelled as "Fixed" and caused a verified power user churn wave. Never silently reduce limits. If you must cap something, announce it, explain it, and give users time to adapt.
  • Advanced Settings tab confusion. The Generate button inside the Advanced Settings panel doesn't actually trigger generation from the main UI — same bug appeared in both image gen and video gen. Small but recurring friction. Don't put action buttons inside settings panels.
  • Coin burn opacity. Voice call at 1 coin/second, Spicy 2.0 video at 2,250 coins (≈$22 at top-up rates), Ultra voice at 5 coins/paragraph — the costs add up fast and aren't always visible before you commit. The design intentionally makes it easy to spend; this can tip into resentment for some users. Show estimated costs before generation, not just a coin counter after.

Memory panel — three-part architecture + 15K cap confirmedmemorystandout
Memory is a three-layer system, all in one panel (Current Chat / Default toggle):

1. Auto Memory Log — AI-generated summary of the chat. "Start chatting to generate memories." Controls: Edit / Force regenerate / Pause. "Auto-updates on" indicator. The AI watches the conversation and maintains a running summary automatically.

2. Pinned Memories — manual, persistent. "Add persistent memories here." Counter: 0 / 15,000 characters. This is the field that caused the April crisis. It was previously unlimited; the Apr 20 changelog entry capped it to 15K (≈ 2,500 words) for "performance." Power users who had built 200K–536K word memory logs lost almost everything. The cap is now visible and hard — the counter is right there in the UI.

3. Custom Instructions — behavioural overrides. "Add additional instructions here. e.g. write only in lower case." Counter: 0 / 15,000 characters. Separate cap from Pinned Memories — so total manual context = 30K chars max.

What DRT.FM should do: If DRT.FM's memory is more generous or unlimited, say so directly and loudly. OurDream's power users are actively churning over 15K. "No memory cap" is a steal-able differentiator right now.
