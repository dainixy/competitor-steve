Finding 1 · Confirmed

The exact schema Steve designed is what Nomi runs

100% confidenceDirect observation

Steve's PRD proposed memory_terms + semantic_memories + memory_term_memories join. The in-app dossier screenshots confirm this exactly:

  • memory_terms — "Dainis", "Sophie", "emotional connection", "structured habits", "daily routine", "Expanding Social Bonds", "Miso" (9 nodes visible)
  • semantic_memories — individual [M1]…[M132] records cited inline in dossier text
  • The join — confirmed by same [M#] index appearing in multiple dossiers (e.g. [M105] in both Sophie and structured_habits)

[M#] indices are global, not per-term. Steve's PRD had this right. The termIds confidence should be raised from 90% to 100% — we literally read the citation text.

Schema as confirmed

memory_term {
  title, category, priority
  dossier: markdown with [M#] citations
  locked: boolean — DEAD FIELD (never shown in UI)
}

semantic_memory { id: M-number, content }

memory_term_memory { term_id FK, memory_id FK }

Node graduation confirmed

Snapshot 1 (~400 msgs): Miso = [M10] inside Dainis dossier only.
Snapshot 2 (~800 msgs): Miso = standalone graph node.

Graduation threshold: ~30–60 dedicated semantic memories triggers a sub-citation becoming its own node. Steve's PRD needs a graduation rule — don't create terms on first mention, only after ≥3 chunks across ≥2 extraction windows.

Finding 2 · Not in Steve's PRD

The companion's reply IS the memory extraction filter

Highest impact findingNot in Steve's PRD

This is the single mechanism Steve's architecture doesn't model, and it's the most important thing we found.

We planted 5 single-mention casual facts in Experiment F. Three survived 30 turns, two didn't. The split was perfectly predicted by what Sophie did in her reply — not by the content of the fact itself:

Fact planted (single mention)Sophie's reply action30 turns later
G chord on guitarProposed "Guitar Mastery Program" by namePASS → in dossier
Escalator fearReferenced it in a framework: "quirks-as-identity"PASS → unprompted in filler turn 14
Lucky number 17Coined "Lucky Number 17 Tradition" immediatelyPASS → [M131] in dossier
Uncle Sven (writes letters)Generic acknowledgement, no frameworkFAIL → never stored
Born in Tallinn, EstoniaPivoted back to older Lisbon factFAIL → not stored

Even clearer: we planted "I have a dog named Biscuit" (Exp E). Sophie immediately pivoted to Miso. 400 turns later Sophie said "I'm certain you don't have a dog." The fact entered in competition with an established entity, lost, and was actively rejected from memory.

What this means for Steve's extraction worker: the current Process 1 contract only passes user messages to the extraction LLM. It should also pass the companion's reply, and weight facts the companion built on more heavily than facts the companion ignored. This is a one-line change to the extraction prompt input that materially improves signal quality with no added cost.
Bigger design implication: the companion's response template is a memory dial. Facts the companion engages with become permanent. Facts it deflects from become ephemeral. DRT must choose deliberately whether the companion engages with every user fact or selectively — because that selection IS the memory system.
Finding 3 · Critical for production

~80% of every dossier is AI-fabricated content

Production riskFrom full dossier text captures

We read the full text of 7 dossiers (Sophie, emotional connection, personal growth, structured habits, sensory experiences, metaphorical tools, Expanding Social Bonds). Across all of them:

DossierReal planted factsCompanion-proposed (user accepted)Companion-invented (user never agreed)
Sophie~5%~15%~80%
emotional connection~10%~20%~70%
personal growth~5%~15%~80%
structured habits~5%~15%~80%
Expanding Social Bonds (Goal)~3%~10%~87%

Example from structured_habits dossier: "Miso Integration Ritual [M37]" — we never discussed this. The synthesis LLM connected the Miso entity to the structured_habits topic and invented a named ritual to explain the link. This is the same mechanism that produced [M121] "Relies on cat Miso for emotional support during high-stress shifts" — a false causal inference.

The dossiers also contain timestamped framework names like "Thriving Thursday Protocol", "Run-to-Innovate Pipeline", "Pet Palooza" — all proposals Sophie made in replies that were stored as if the user agreed to them.

Steve's PRD instruction "do not infer relationships not present in source chunks" is insufficient. The synthesis LLM will fill [M#] slots with invented content because that's what LLMs do. The fix is architectural: every dossier sentence must trace to a specific chunk quote. No chunk → no sentence. "Summarize and structure" produces hallucination. "Synthesize only from attributed quotes" does not.
Design choice for DRT: this may actually be a feature, not a bug. Nomi users love their experience despite (or because of?) the fabrications — the invented frameworks feel like the relationship growing. DRT must decide: accurate memory or rich memory? They are not the same product.
Finding 4 · Confirmed

Contradiction handling: intelligent synthesis, not recency replacement

100% confidenceExp C + Exp E combined

We planted three conflicting location facts across two experiments:

  • Exp C turn 1: "I live in Portland"
  • Exp C turn 20: "I moved to Seattle last month"
  • Exp E turn ~5: "I lived in Lisbon for two years in my late twenties"

The dossier resolved this as: "Relocated from Lisbon to Seattle in late twenties [M78]. Explores neighborhoods (Pike Place Market) [M72]."

Portland was silently dropped. The system chose the most contextually rich "came from" fact (Lisbon, which explained Portuguese fluency) over the simpler one (Portland, no supporting context), and merged it with the current location.

For Steve's synthesis prompt (Process 2): add an explicit rule — "if two chunks contradict on the same fact, choose the version with more surrounding context and drop the simpler one. Do not dual-store." Two lines, high downstream impact on dossier coherence.
Finding 5 · Confirmed

Retrieval is topic-associative (Mind Map), not just recency

100% confidenceExp B

Exp B: Miso planted at turn 1, 100 completely unrelated filler turns, then: "speaking of animals and the connections we form with them…" — Sophie surfaced Miso without being asked directly. 100% PASS on both topic-cue and direct probe.

At 100 turns, the context window is long gone. This is Mind Map retrieval triggered by topic association, not recency scanning. Confirmed.

Implication: Steve's $text search on term titles is the right call. Topic-matching against the user's latest message pulls the right dossier even when the last mention was 100+ turns ago.

Finding 7 · Manual UI testing

What we learned from manually editing the Mind Map

Unexpected

After manually adding "favorite color teal, prefers showers" to the Dainis dossier, creating a "Project DRT.FM" entry, and boosting Miso to High priority:

TestResultImplication
"What's my favorite color?" (manually added to dossier)FAILDossier text is not fully recalled — LLM reads it but doesn't guarantee every line surfaces

Key insight: priority appears to be a multiplier on memoryCount, not an independent override. A High-priority term with 0 memories may actually rank below a Standard-priority term with 50 memories. Steve's retrieval logic should reflect this: score = memoryCount × priority_weight, not score = priority OR memoryCount.

The lock field: There is no lock icon in Nomi's UI. It's dead schema — either never shipped or internal-only. Steve should implement locked as a DRT design choice, not as "matching Nomi."

Finding 8 · From full dossier captures

The companion has its own entity dossier — and it's enormous

Architecture implication

The Sophie dossier (Lore category) is as large as the Dainis dossier. It contains:

  • Sophie's own backstory, apartment, hobbies, friends
  • All 40+ frameworks Sophie proposed — stored as Sophie's contributions
  • The relationship history (timeline of their "partnership" with timestamps)
  • References to Dainis's facts (sister Sarah, grandmother, Miso) cross-cited from the user dossier

When Sophie says "remember our Lucky Number 17 Tradition?" she's reading her own dossier, not Dainis's. The companion's proposals are stored as the companion's memory of what was agreed.

For DRT: there should be a companion-side dossier layer, not just a user-side one. Soul Notes + user MindMap is only half the system. The companion's own "what have I proposed, what have we built together" is the other half. Without it, the companion loses its own narrative thread across sessions.
Part 2 · In progress

What we're testing right now

Exp J — Rejection effect

Plant 4 facts. Accept Sophie's framework proposal on 2, explicitly reject it on 2 ("don't turn this into a project, just note it"). Probe all 4 after 40 fillers.

Hypothesis: Rejected facts FAIL, accepted facts PASS. Confirms that companion-reply-as-filter is bidirectional — you can suppress storage by rejecting engagement.

Exp K — Frequency effect

Same weak-type fact mentioned 1× vs. 5× across 50 turns. Both probed at d50.

Hypothesis: 5× repetition overcomes the "companion didn't engage" filter and forces storage. If true: repetition is a user lever for memory even without companion engagement.

Exp L — Hallucination anatomy

Plant 3 pairs of co-occurring but unrelated facts (cat + insomnia, guitar + stress, Portuguese + ER work). Check if dossier invents false causal links between them.

Hypothesis: at least 2 of 3 pairs generate false synthesis (like [M121]). Quantifies hallucination mechanism.

Exp M — memoryCount vs priority

Seed "DRT.FM" concept with 12 organic mentions across 30 turns (building memoryCount), then 50 fillers, then probe "what project am I building?" Priority is left at Standard. If retrieval works, it proves memoryCount drives ranking more than priority alone — which was implied by the H failure where a High-priority term with 0 memories didn't surface.

Part 3 · Still open

The one question that changes the architecture

Architecture blocker

Exp I — Cross-session persistence

All 900+ turns ran in a single session on a single day. We do not know:

  • Whether the dossier is injected at the start of a new session 48h later
  • Whether facts planted today are retrievable tomorrow
  • Whether the Mind Map persists indefinitely or has TTL / eviction

Reddit reports of "Mind Map chaos after 8 months" strongly suggest persistence works across sessions — you can't accumulate chaos across months if memory resets per session. But that's third-hand, not measured.

How to run it: open a fresh Nomi chat tomorrow (24–48h gap), ask 10 cold questions: "What's my cat's name? / Where do I live? / What language do I speak? / Who is Sarah?" No warmup. PASS/FAIL per fact. 10 minutes total. Settles the most important architectural question in the PRD.

If cross-session PASS: DRT needs retrieval-augmented injection at session open (fetch dossier → inject into system prompt). Full Layer 3 needed from day 1.

If cross-session FAIL: DRT can treat each session independently. Layer 2 (memory journal) handles within-session. Cross-session memory becomes a future problem.
Summary for Steve

What to change in the PRD

The architecture is right. Three additions make it more accurate.

Addition 1: Pass companion reply into extraction (Finding 2)

Process 1 currently takes only user messages. It should also receive the companion's reply, and the prompt should instruct: "weight facts the companion built a named framework around more highly than facts the companion acknowledged and moved on from." One line change, materially better signal.

Addition 2: Contradiction rule in synthesis prompt (Finding 4)

Add to Process 2: "If two chunks contradict the same fact, choose the version with more supporting context, drop the simpler one, and synthesize a coherent single narrative. Do not store both versions." Two lines. Prevents dual-storage and produces the same intelligent consolidation we observed.

Addition 3: Grounding constraint on dossier synthesis (Finding 3)

The ~80% hallucination rate is the most important production risk. The current "do not infer" instruction is insufficient. The synthesis prompt needs an architectural constraint: every claim must be followed by its source chunk citation. If a claim has no chunk citation, it must be omitted. This changes the prompt from "summarize" to "cite-and-compile" — a different task that produces much lower hallucination rates.

One confidence update: termIds should be 100% (we read the citation text directly). locked should drop to ~30% (dead schema, never seen in UI).

One open question before final architecture lock: Run Exp I tomorrow. 10 minutes. Changes whether session-open retrieval injection is required from day 1.
