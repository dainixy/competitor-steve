1The answer in one paragraph

Claude's default design output is generic because it is the statistical average of all web design — that's literally what "generic" means. Every credible practitioner fixes it the same way: stronger inputs (a written design system + named references instead of "modern and clean"), tighter guardrails (taste skills that ban the known AI-slop patterns), and feedback loops (Claude looks at a screenshot of its own page and critiques it — because Claude is a much better critic than generator). Both research streams — my verified web sweep and Kimi's social sweep — converged on this independently. The stack implementing all three layers is already installed on this Mac and works in every Claude Code session, including the DRT.FM prototype chat.

The working loop for the DRT.FM prototype chat

  1. Before building: point Claude at the project's DESIGN.md (being written next — see §7). Never say "modern and clean"; name the direction and reference.
  2. Build — the taste skills constrain generation automatically.
  3. De-slop: /design-deslop or /baseline-ui.
  4. See it: "run a live design review on <preview URL>" — fixes what code review can't catch, plus a Lighthouse speed gate.
  5. You judge. Ask for 3–5 visual variants of any screen you're unsure about and pick — AI is cheap at variants, bad at knowing which is good. Your taste is the selection function.

3The 11 methods, ranked by evidence

From 52 adversarially verified findings. "Both streams" = my web sweep and Kimi's social sweep found it independently.

1 · Give Claude eyes — screenshot feedback loop STRONG INSTALLED

The single most independently converged-on fix (both streams, 5+ unrelated practitioners, a 296K-view tutorial). Claude writes UI blind; most "bad taste" is actually unreviewed output. Wire in a browser, let it look at what it built, and it fixes the padding, dead buttons, and broken layouts it couldn't see. Ours runs through the chrome-devtools connector you already had — with a Lighthouse speed audit added.

2 · Taste skills — written as principles, not pixel rules STRONG INSTALLED

The counterintuitive finding, proven twice independently: exact hex codes and pixel values make output worse and samey; evocative principles make Claude think ("squint test: blur your eyes — can you still see hierarchy?"). Justin Wetch ran the only blind eval in this space — his principle-based rewrite of Anthropic's skill won 75% of 50 blind judgments (Google's Paul Irish engaged). His SkillEval workbench is stashed in our reference folder for A/B-testing our own rules later.

3 · Name the aesthetic, feed references STRONG

"Modern and clean" returns the average. "Brutalism: 4px black borders, monospace, broken grid" returns a design. Best verified demo: on-camera controlled comparison (174K views) — skill + reference screenshot beats skill alone beats baseline. Drag screenshots of sites you admire into the prototype chat; hallmark study <URL> formalizes this into a portable design file. Meng To's motto from the sweep: "references beat paragraphs, specs beat vibes."

4 · Self-critique passes STRONG INSTALLED

Generation and evaluation are different tasks — a dedicated review pass catches slop the generation pass literally cannot attend to. Installed as three flavors: the live-browser reviewer, the /design-deslop static pass, and the chained ibelick cleanup commands. The zero-install version that also works: "Go through the page you just created and improve it significantly: reflect on mistakes, inconsistencies, anything visually off."

5 · Persistent design memory — one written source of truth STRONG partially — DESIGN.md next

Claude forgets decisions between sessions, so buttons drift 36→38→40px across days. Consistency IS most of what reads as "designed." One file, re-read every session. Critical nuance from the sweep: tokens alone fix colors but not layout — the file must also contain component recipes in prose ("Card = image full-bleed, 12px radius, text on scrim; used for X, not Y"). This is DRT.FM's DESIGN.md — the one per-project piece, drafted next from the teardowns below.

6 · Parallel variant fanout MEDIUM-STRONG

Never accept the first design. Have Claude build the same screen 4–8 ways as plain HTML files, pick the winner, iterate only on that. AI is cheap at variants and bad at judging them; you are the reverse. This converts your taste from bottleneck into selection function — and it's how a shipping founder on HN got his live site.

7 · Component grounding MEDIUM-STRONG

Left alone, Claude hallucinates a slightly different button every time. Ground it in a real component library and ban invention explicitly — the sweep's most-verified detail: polite requests don't stop improvisation, only hard "NEVER build from primitives" rules do. For DRT.FM: shadcn MCP inside the project repo (one command, noted in manifest) or a Storybook page per component.

8 · Figma as ground truth MEDIUM — needs Figma designs

If a human-made design exists in Figma, an MCP bridge (Framelink, 15.4k★) feeds the real layout to Claude — removing taste from its job entirely. Relevant later if you commission screens; not blocking now.

9 · Measure, don't eyeball MEDIUM

Screenshots can fool the judge; computed styles can't. Extract rendered pixel values and diff them against the spec numerically ("gap is 40px, spec says 24px"). One senior engineer's rigorous write-up; our anatomy-gate work on Nadia already proved this philosophy for us. Cheap to add to the review agent later.

10 · Multi-model composition MEDIUM — calibration signal

Some practitioners hand the visual phase to a cheaper model and let Claude plan + ship. Included as an honest data point about Claude's native design ranking, not a recommendation — our stack addresses the gap differently.

11 · The 5–20% rule — the human owns final polish MEDIUM-STRONG as a norm

Designers at Notion, Ramp, and enterprise teams all describe the same shape: AI gets UI 80–95% there; shipped quality comes from a human owning the last stretch. Every verified high-quality outcome in this research had a human decision-maker at the moment of taste. That's your role in the loop — nobody found a way to delegate it.

4Candy.AI teardown — what makes it feel premium

Headless-browser analysis at 1440px: landing, gallery, pricing, live chat, creator wizard, 404, empty states + computed styles across ~4,000 DOM nodes. Full data in .scratch/design-taste/. Every rule below is restated to transfer to a different visual identity — these are disciplines, not their look.

The big strategic one: the landing page IS the product

Logged-out homepage renders the real app shell — sidebar, character grid, filters, search. Visitors browse immediately; marketing prose is pushed below the fold as quiet article text (still there for SEO). No hero-headline-two-buttons template anywhere.

Color & depth

  • Near-black #131313 canvas, elevation by background steps (#252525 → #303030) + 10%-white hairlines. Across ~4,000 elements, almost zero box-shadows — shadows only on true overlays.
  • One accent (their pink) with an enumerated job list: primary CTA, active-nav marker, one accented headline word, selection rings. Every other color has exactly one meaning (red=LIVE, gold=discount).

Type & shape

  • One typeface. Effective scale ~6 sizes; hierarchy from weight (400/500/600) and dimming, not more sizes. 14px/500 dominates all UI labels — one voice.
  • Exactly four radius values, each bound to a component class (pills, 24px media cards, 10px buttons, 8px controls). The consistency itself reads as engineered.

Cards & content

  • Cards are 100% image — no border, no padded frame; text overlays a bottom gradient scrim.
  • Card copy is a narrative hook in second person ("Your stepmom catches you in the act!"), not metadata. Copywriting is a design material.
  • Hover = content preview (still swaps to autoplaying video), never CSS zoom. 150ms color transitions elsewhere.

Flows & trust

  • Chat never opens empty — the character has already sent an in-character opener; the composer teaches premium features as tappable chips.
  • Pricing: one viewport, three cards, only the recommended plan carries color. Trust microcopy at the anxiety point: bank-statement discretion + cancel path directly under the buy button.
  • Empty states are the action drawn at content size ("Create new AI" tile occupying the future card's slot). Custom-illustrated 404.

5OurDream teardown — consistency by architecture

Same method, deeper find: they run a genuine internal design system — ~400 CSS design tokens in three tiers. Their polish is mechanical, not heroic. This is the model for DRT.FM's DESIGN.md.

Token architecture (the master move)

  • Primitives → roles → component aliases; every interactive color ships with hover/active/disabled variants defined together, so no state is ever improvised.
  • Motion tokenized: 5 durations (100–600ms) + 5 easing curves. Nothing animates at an ad-hoc speed.
  • Radius histogram: 12px on 162 elements, nothing off-scale. "One giant spike, not a smear."

Accent scarcity

  • Accent occupies under 2% of any screen. Banned from icons, borders, links. Only: money actions (Join/Upgrade/Subscribe), the premium badge, selected-plan border.
  • Three CTA tiers: accent pill (max one per region) → inverted white pill → gray/ghost. Paired actions get inverse + surface, never two accents.
  • Content imagery owns the color budget; the chrome stays monochrome.

Craft details that read expensive

  • Image scrims use 15+ gradient stops shaped like an easing curve — no visible "band edge." The single biggest expensive tell on their cards.
  • Hover: scale(1.02), 200ms, ease-out, grid cells overflow-visible so it never clips. That's the entire effect.
  • Dark theme designed, not inverted: #0d0d0d page (never #000), three graded text tones, styled scrollbars, dark-first paint with zero white flash.
  • Overflow always designed: 2-line clamps, "+17 more" counter chips, fading horizontal rails.

Conversion surfaces

  • Pricing converts abstract credits into concrete outputs: "1000 Dreamcoins = 200 images / 20 min voice / 10 videos." (Directly relevant to our gen-credit model.)
  • Promos inherit exact content geometry — a sale banner occupies one standard grid cell. Marketing never breaks the grid.
  • Search placeholder teaches by example — a sample query you could type verbatim, not "Search...".

Their one measured weakness — our opening

OurDream loads 8+ font families (Poppins + owners variants + Neue Haas + Geist) — a real performance cost. Our speed-first constraint (one or two font families, budget-enforced) can beat both competitors on Core Web Vitals while matching their discipline. Neither site's polish requires weight.

These 28 principles + our 33 hands-on observations from the paid-account sessions (OurDream: guided creator with visual pickers, per-chat sliders, background generation with notification bell, best-in-category cancellation; both: verdicts logged in competitor-checks.html) become DRT.FM's DESIGN.md. Deliberately NOT copied: pink accents, near-black-with-pink identity, their fonts — identity stays ours.
