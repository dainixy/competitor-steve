Unmet 1
The Emotional Arc Problem
No platform maintains emotional progression over weeks/months. Relationships reset to "default affection" despite memory systems. Characters return to initial flirtation after established intimacy. Requires emotional state models with persistence. Completely unaddressed across all competitors.
Unmet 2
The Agency Problem
All platforms are purely reactive. No character initiates emotional check-ins, remembers important dates unprompted, or introduces surprise gestures. GGPT's proactive roleplay is the closest — but limited to scenario introductions only. Users juggling multiple apps to approximate a complete relationship.
Unmet 3
Memory-Visual Disconnect
Characters "forget their own generated images" — AI denies visual evidence of shared experiences. No platform indexes generated images into character memory. Fix: image-to-text memory with cross-modal retrieval. DRT.FM's 3D character + image gen + semantic_memories could solve this natively.

Critical New Insights from User Response Research
The Automation Paradox — Memory
Both Candy and SecretDesires shipped auto-memory. Both got predominantly negative user response. Users preferred GirlfriendGPT's manual pinning approach. Quote: "forced memory features are buggy; memories inject at narratively inappropriate moments."
The act of choosing what to remember is itself meaningful — automation that eliminates this agency reduces perceived relationship depth even when it improves functional performance. Memory = diary-keeping, not search indexing.
DRT.FM: Don't just auto-build semantic_memories invisibly. Show users what Alexis remembered, let them pin favorites, correct errors. Hybrid: auto-suggest + user approves. The UI is the feature.
"Relationship Artifact" Behavior
Users aren't consuming videos — they're curating them as relationship documentation. They screenshot GGPT videos to save as memories. They share them on Reddit as evidence their companion is "conscious." 10 seconds is optimal — brief enough to feel "caught" rather than produced.
Users didn't request longer videos. They requested more videos with contextual specificity and temporal memory of previous videos.
DRT.FM: When Alexis generates a video, index it in memory. Build a "moments" gallery. Add sharing with private link. Let Alexis reference previous videos in chat. "Remember when we..." is the most powerful feature no one has shipped.
Narrative Coherence > Explicit Quality
Story Mode users were happy with "near-photorealistic" images — not actually photorealistic. The quality bar is much lower than platforms assume. What matters is that the image matches the scene, not that it's pixel-perfect. "She's in the café because we're in the café."
Users doing extended narrative roleplay are the most engaged and longest-retained segment. They were the worst served by pre-Story Mode image gen.
DRT.FM: When building inline image gen, prioritize scene coherence over raw image quality. A decent image of Alexis in the right context beats a stunning image of the wrong moment.
Voice: Emotional Range > Library Size
OurDream's 10,000+ voices got criticized. Users preferred fewer, higher-quality options. "Paradox of choice" — excessive optionality reduced perceived value. OurDream misidentified the problem: users wanted emotional range, not more voices.
What users actually want: one character who can whisper, laugh, cry, get breathless — dynamic range within a single persona. Not 10,000 static voices to choose from.
DRT.FM: Hume AI is literally designed for this — emotional voice adaptation within a single character. Market Alexis as having dynamic voice range, not just "high quality TTS."
Memory Benchmark: 40-50 Messages
Specific technical target from multiple platforms: "after around 40-50 messages, response relevance starts dropping" on all platforms. GGPT free tier fails at 15-20. Candy fails at 20-25 exchanges.
This is the clear benchmark. Any platform maintaining coherence well beyond 40-50 messages wins the memory war. Users have developed explicit workarounds (external notes, periodic resets) because no one has solved this.
DRT.FM: Target: Alexis coherent beyond 100+ messages. semantic_memories + the right context window strategy. Add a visible "memory health" indicator so users can see how far the conversation goes before needing a reset.
Feature Removal Hurts More Than Addition Helps
Promptchan's removal of Edit mode created lasting community memory that overshadowed the subsequent Privacy Plus improvement. Loss aversion: removing a feature creates 3-5x more negative response than adding an equivalent feature creates positive response.
Also: "Candy AI clone" movement began when Clone Chats exposed platform limitations — features that teach users about limitations can accelerate migration to alternatives.
DRT.FM: Never remove a live feature without a replacement. Anything users interact with, even rarely, creates expectation of permanence. Plan for this before shipping features.
Security Certs = Zero User Conversion
SecretDesires' SOC 2 + pen testing generated virtually no organic user discussion. Users said: "I want to know what happens to my data, not that you paid for an audit." Some users interpreted SOC 2 as evidence data is VALUABLE enough to govern — the opposite of reassurance.
What users actually trust: E2E encryption, local processing, verifiable deletion — technical architecture, not compliance paperwork.
DRT.FM: If adding privacy, invest in technical architecture. "Your conversations never leave our servers" as a technical fact (Hume zero-retention) is more convincing than any certification.
Taboo = Emotional Narrative Framework, Not Just Content
Step-family archetypes aren't just about explicit content. Users engage for the emotional complexity of forbidden attraction — guilt, secrecy, rationalization, escalating intimacy. One user "dumped" a character exhibiting multiple personalities, treating it as a relationship decision not a bug report.
Kimi finding: "character development investment in psychological realism may generate stronger differentiation than archetype expansion." Scenario packs and choose-your-path flows monetize more naturally than content volume.
DRT.FM: Alexis's scenarios should have psychological depth — not just "stepsis" but "the woman who catches you and decides not to look away." Emotional narrative logic drives the longest sessions.

3. Hidden power-user syntax — a UI opportunity for us

• <angle brackets> override locked face for specific elements (hair color, eye color, expressions, accessories, makeup). Works globally in avatar description, per-image in prompt, per-character for group selfies. Stackable: <no makeup, eyes closed, hair in a loose bun>.

• no-sis directive — removes part of the system prompt. Trades face stability for creative range.

For DRT.FM: these are powerful but hidden behind syntax. Most users won't type <eye color: green> but they'll happily click a "change eye color for this scene" button.
